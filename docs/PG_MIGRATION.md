# Beebo: SQLite → PostgreSQL Migration

Multi-phase migration. This phase changes **no application code**.

## Ground rules (verbatim, apply to every phase)

1. beebo.db is production data. Never write to it. Open it only read-only (sqlite3 URI `file:beebo.db?mode=ro`, `uri=True`) or work on a copy.
2. Tests and experiments only ever run against throwaway databases whose name starts with `beebo_test`. Never run the app or tests against any other database.
3. Work only on git branch `postgres-migration`. Never commit `beebo.db`, `.env`, or credentials. Commit per phase with a short message. Do not push.
4. Do not change API response shapes, route behavior, or frontend files.
5. Out of scope: sharding, ORM, pgbouncer, changing the single-process model (in-process rate limiter, long-poll signalling), frontend work.
6. At the end of each phase, print a report: what changed, files touched, gate results (pass/fail with evidence), open risks. Stop there.

## Decisions

- **PostgreSQL 16.**
- **psycopg 3 + psycopg_pool** (not psycopg2, not an ORM).
- **Raw SQL** — no query builder; keep the hand-written statement style.
- **`DATABASE_URL` env var, no fallback.** Missing var = hard error at startup. (During transition the SQLite path code remains, selected by which env var is present; final cutover removes SQLite.)
- **ids: `BIGINT GENERATED BY DEFAULT AS IDENTITY`** (replaces `INTEGER PRIMARY KEY AUTOINCREMENT`; allows explicit id inserts during data transfer).
- **timestamps: `TIMESTAMPTZ`** with connection `TimeZone=UTC` and unchanged API output format (ISO-8601 `...Z`, same as the wallet already emits).
- **Tuple rows** — keep `row[0]`-style positional access where present; no dict-row rewrite in this migration.
- **Unique index on `lower(username)`** (replaces SQLite `COLLATE NOCASE` semantics).
- **Numbered `.sql` migrations kept** — the `migrations/NNN_*.sql` convention continues; Postgres-specific migrations get new numbers after 008.

### How to start PostgreSQL 16 with Docker (run this yourself — no sudo needed)

```bash
docker run -d --name beebo-pg \
  -e POSTGRES_USER=beebo \
  -e POSTGRES_PASSWORD=beebo \
  -e POSTGRES_DB=beebo \
  -p 5432:5432 \
  -v beebo_pg_data:/var/lib/postgresql/data \
  postgres:16-alpine
```

Then verify:

```bash
docker exec -it beebo-pg psql -U beebo -c 'select version();'
# expect: PostgreSQL 16.x
```

Stop / start / remove:

```bash
docker stop beebo-pg        # stop
docker start beebo-pg       # restart (data persists in the named volume)
docker rm -f beebo-pg       # remove container (data volume beebo_pg_data remains)
docker volume rm beebo_pg_data   # drop the data volume entirely (destructive)
```

Connection string for later phases:

```
DATABASE_URL=postgresql://beebo:beebo@localhost:5432/beebo
```

Do not install system packages or use `sudo` (ground-rule scope). If
Docker is not usable in the environment where phase 2 runs, the exact
package-based install (outside this repo) would be: install `postgresql-16`
+ `libpq-dev`, `initdb`, start via `pg_ctl` — but that path is not taken
here because Docker is already available.
